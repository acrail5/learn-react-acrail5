\---



\## Week 1: React Basics and Components



\### Weekly Goal



Learn the basic structure of a React app and understand how components work. Practice editing a React project, making components, and using JSX.



\### Recommended Resources



\- React official Quick Start: https://react.dev/learn

\- Vite official guide: https://vite.dev/guide/

\- MDN React getting started: https://developer.mozilla.org/en-US/docs/Learn\_web\_development/Core/Frameworks\_libraries/React\_getting\_started



\### What I Should Practice



\- Run the React project with `npm run dev`

\- Edit `App.jsx`

\- Create simple components

\- Use JSX correctly

\- Pass simple data using props



\### Milestones



\- I can start my React project locally.

\- I can explain what a component is.

\- I can create at least 2 custom components.

\- I can display text, headings, buttons, and simple layout content.



\---



\## Week 2: State, Events, and Forms



\### Weekly Goal



Learn how to make the frontend interactive by using state, click events, and forms. This will help me prepare for login forms and recipe input forms.



\### Recommended Resources



\- React official guide on adding interactivity: https://react.dev/learn/adding-interactivity

\- React official guide on managing state: https://react.dev/learn/managing-state

\- MDN JavaScript forms and events review: https://developer.mozilla.org/en-US/docs/Learn/Forms



\### What I Should Practice



\- Use `useState`

\- Handle button clicks

\- Create controlled form inputs

\- Save form values in state

\- Display form results on the page



\### Milestones



\- I can create a form in React.

\- I can type into inputs and store the values in state.

\- I can handle a submit button.

\- I can build a simple login form layout, even if it does not connect to the API yet.



\---



\## Week 3: Fetching Data from a REST API



\### Weekly Goal



Learn how to connect React to a REST API using `fetch`. Practice getting data from an API and showing the results on the page.



\### Recommended Resources



\- MDN Fetch API guide: https://developer.mozilla.org/en-US/docs/Web/API/Fetch\_API/Using\_Fetch

\- React official guide on effects: https://react.dev/learn/synchronizing-with-effects

\- React official guide on rendering lists: https://react.dev/learn/rendering-lists



\### What I Should Practice



\- Use `fetch`

\- Use `useEffect`

\- Store API data in state

\- Display data using `.map()`

\- Show loading and error messages



\### Milestones



\- I can request data from an API.

\- I can display a list of items from API data.

\- I can show a loading message while waiting.

\- I can show an error message if the request fails.



\---



\## Week 4: Authentication and Final Frontend Preparation



\### Weekly Goal



Learn how to handle login and authenticated requests. Build the basic structure needed for my final frontend that connects to my course REST API.



\### Recommended Resources



\- MDN Fetch API guide: https://developer.mozilla.org/en-US/docs/Web/API/Fetch\_API/Using\_Fetch

\- React official guide on sharing state between components: https://react.dev/learn/sharing-state-between-components

\- React Router tutorial: https://reactrouter.com/start/declarative/routing



\### What I Should Practice



\- Create a login form

\- Send username and password to the API

\- Save the returned authentication token

\- Use the token in future API requests

\- Create simple pages or views for login, home, and protected data



\### Milestones



\- I can submit login information from a React form.

\- I understand that authenticated requests usually need a token in the request header.

\- I can store a token temporarily for testing.

\- I can make a request to a protected API route.

\- I have a plan for my final frontend project.



\---



\## Final Goal by the End of Week 5



By the end of week 5, I want to have a working React frontend that connects to my REST API. The frontend should let a user log in, store the authentication token, and make authenticated requests to the API. I also want the frontend to show data from the API in a clear and organized layout.



For my project idea, I want to continue building toward a recipe organizer called ForKingRecipe. The frontend could allow users to log in, view recipes, add recipes, and organize recipe information.
